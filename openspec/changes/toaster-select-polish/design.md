# Design

## Context

Verified against source (Sonner 2.0.8, `node_modules/sonner/dist/index.js`):

- Sonner injects its stylesheet unlayered. Tailwind 4 utilities live in `@layer utilities`, and an unlayered rule beats any layered one regardless of specificity. So `classNames` with plain utilities lose against Sonner's `[data-sonner-toast][data-styled=true] ...` rules, as the Sonner guidance says ("every class needs `!important`").
- Sonner defines its palette as CSS variables on `[data-sonner-toaster][data-sonner-theme=light|dark]`: `--normal-*`, `--success-*`, `--info-*`, `--warning-*`, `--error-*` (bg, border, text), `--normal-bg-hover`, `--normal-border-hover` (dark only), and `--gray1..12`. An inline `style` on the toaster element beats those rules, so the variables can point at `--rixl-*` tokens and then follow whatever theme the ancestor sets.
- Rich colours only apply when `data-rich-colors="true"`, set by the `richColors` prop.
- Constants that variables cannot reach: description colour (`#3f3f3f`, or `#e8e8e8` for the dark theme), the `rgba(0,0,0,.x)` focus rings, the 4px button radius, 24px button height, and `box-shadow: 0 4px 12px rgba(0,0,0,.1)`.

## Toaster decisions

| Decision                                         | Why                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Variables via inline `style`, not `theme`        | Tokens already switch with `[data-theme]`; a `theme` prop would need React state, and `"system"` follows the OS rather than the rixl attribute. `theme` stays the consumer's to pass.                                                                                                                                                                     |
| Rich colours from `color-mix` of existing tokens | No new token. Background `10%` and border `30%` of the feedback colour over `--rixl-surface`; text `55%` feedback colour over `--rixl-fg`, because the raw `--rixl-warning` and `--rixl-success` fail 4.5:1 as text on a light surface. Mixing toward `--rixl-fg` darkens on light and lightens on dark. Contrast is measured by axe in the browser test. |
| `richColors` defaults to `true`                  | The requirement is that success, error and warning toasts use the feedback tokens; Sonner only applies the `--success-*` variables with rich colours on. Opt out with `richColors={false}`.                                                                                                                                                               |
| Info stays neutral                               | There is no `--rixl-info` token and adding one is not needed for this change.                                                                                                                                                                                                                                                                             |
| Overrides with Tailwind `!`                      | Needed for what variables cannot reach (list above). Few, and per part.                                                                                                                                                                                                                                                                                   |
| Sonner's motion untouched                        | 400 ms ease enter, exit and stack is Sonner's documented timing. Its reduced-motion rule already disables it.                                                                                                                                                                                                                                             |

## Select decisions

- Indicator: verified in `@base-ui/react@1.9.0` (`select/item-indicator/SelectItemIndicator.js`, `utils/ItemIndicator.js`): the Select indicator renders only while `selected`, and `useTransitionStatus(selected)` is called without `animateInitialOpen`, so it mounts already settled and `data-starting-style` never fires. Copying the `DropdownMenu` classes (`data-starting-style:scale-50 ...`) would therefore change nothing visible. Instead the indicator uses `keepMounted` and the item's `data-selected` (which Base UI sets on `Select.Item`) drives `scale-50 opacity-0` to `in-data-selected:scale-100 in-data-selected:opacity-100` with `transition-[scale,opacity] duration-(--rixl-motion-fast) ease-out motion-reduce:transition-none`. A plain CSS transition is interruptible. The browser test uses Base UI's root with `multiple`, because the wrapper `Select` types a single value, and checks that `getAnimations()` lists CSS transitions on `scale` and `opacity`. In a single Select the popup closes on selection, so the transition only shows during the popup's own exit.
- Cursor: `cursor-default`. Menu items and native `<option>`/`<select>` popups use the default arrow; a pointer cursor is for links. Base UI's own Select and Menu demos use the same default. Keeping both on `cursor-default` makes the two popups feel the same.
- Refs: leaf parts are wrapped in `forwardRef` with a `displayName`, as the repository rule requires for React 18 peers. `SelectGroup` is included because it renders a DOM element.
- `SelectValue` renders a DOM element via Base UI; it is wrapped as well.
- Chevron rotation and popup transitions already use `duration-(--rixl-motion-fast)`, `ease-out` and `motion-reduce:transition-none`; no change.

## Found while there

- `color-mix(in oklch, ...)` between a feedback colour and `--rixl-surface` (`oklch(1 0 0)`) interpolated the hue toward 0 and turned success, error and warning toasts the wrong hue (measured: success background hue 14.5 instead of near 145). `oklab` has no hue interpolation; a browser test checks the red-green axis of success and error backgrounds.
- `toastOptions.classNames` passed by a consumer replaced all the wrapper's defaults. They are now merged per part with `cn`.
- The wrapper `Select` does not type `multiple` (it drops Base UI's `Multiple` generic and its `onValueChange` is single-valued). Left alone: adding it is a feature, not polish.
- `invert` on the Toaster sets literal `#000` and `#fff` in Sonner's stylesheet, which tokens cannot reach. Not handled; `invert` toasts keep Sonner's colours.
- Preset-wide, not fixed here: `@theme` in `preset.css` registers `--color-rixl-*: var(--rixl-*)` without `inline`, so Tailwind resolves each once at `:root`. `data-theme="dark"` on `<html>` works, but on a nested ancestor the `bg-rixl-*`, `text-rixl-*` and `shadow-*` utilities keep their light values (observed in a screenshot: a nested dark scope showed the light primary and secondary action buttons, and `bg-rixl-bg` stayed light), while plain `var(--rixl-*)` declarations such as the Toaster's inline variables do re-theme. `preset.css` says "html (or any ancestor)". Browser tests therefore put `data-theme` on `<html>`. A fix (`@theme inline`) changes every component's resolved values and belongs in its own change.
